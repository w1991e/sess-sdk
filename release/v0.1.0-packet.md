# Release packet: 0.1.0 on `latest` for all four packages

This is a maintainer document and is not packed. Preparing it publishes nothing. Tags, the protected-environment approvals and the npm 2FA stage approvals are owner actions.

Goal: `latest` moves from the `0.0.0-stage` placeholder to `0.1.0` on `@sess.si/sdk`, `@sess.si/mcp`, `@sess.si/openclaw` and `@sess.si/create-agent`, in one sequence, through the release workflows only. There is no manual dist-tag move. Every 0.1.0 package carries `license: Apache-2.0` and its `LICENSE` file.

## Order

1. **SDK 0.1.0** (this packet's commit): tag, stage, approve. `latest` becomes `0.1.0`.
2. **Registry transition:** `npm run pin:update` on master after step 1. Consumers move from `0.1.0-rc.9` straight to the published `0.1.0`. rc.10's own transition is not needed, because nothing on master consumes rc.10. Then the MCP `sdk:switch-to-registry -- --apply`, and the OpenClaw `sdk.evidence` for the 0.1.0 release run.
3. **The openclaw guard change (sess-sdk #26):** rebased onto master, fresh CI, merged before any `openclaw-v0.1.0` tag. Until it is merged, the openclaw guard refuses stable versions.
4. **Each adapter's 0.1.0 release-prep PR** (one PR each, independent review): MCP, OpenClaw, create-agent. Each bumps the package to `0.1.0` with its exact SDK dependency at `0.1.0`, dates its CHANGELOG, and updates its packed-check expectations. For OpenClaw, from ASTRA's notes on #26:
   - `adapters/openclaw/scripts/check-package.mjs`: the expected tarball name, `sess.si-openclaw-0.1.0.tgz`;
   - `adapters/openclaw/README.md`: the dist-tag lines (`latest` is the release, not the `0.0.0-stage` placeholder);
   - `adapters/openclaw/compatibility.json`: version, `distTag: latest`, status and publication, following `checkCompatibilityStatus`;
   - `adapters/openclaw/scripts/registry-sdk.mjs`: its comment about the SDK on `next`.
5. **Tags in order**, `mcp-v0.1.0`, `openclaw-v0.1.0`, `create-agent-v0.1.0`, each staged and approved like the SDK.
6. **Readback:** `node scripts/check-latest-release.mjs 0.1.0` (from #26). It must report `latest is 0.1.0` on all four, each Apache-2.0 with its LICENSE file.

## What SDK 0.1.0 contains

The `0.1.0` entry in [`CHANGELOG.md`](../CHANGELOG.md):

- The API of `0.1.0-rc.10`, unchanged.
- One development-only fix: the advisory GHSA-g3hv-75wg-m249 (minimatch below 11.0.1). It reached `npm audit` through `openapi-typescript` → `@redocly/openapi-core` 1.34 → `minimatch` 5.1.9, and blocked required CI. The root `package.json` gains a scoped `overrides` entry, `{"@redocly/openapi-core": {"minimatch": "11.0.1"}}`, with its lockfile.
  - npm ignores `overrides` for consumers, so installing `@sess.si/sdk` is unaffected.
  - The generated types are byte-identical: `src/generated/openapi.ts` sha256 `dac73121…0198` before and after.
  - `@redocly/openapi-core` 1.34 calls minimatch only when it fetches a remote `$ref` with header rules configured. The contract has no external `$ref` and no header rules, so the changed export is never reached during generation.

Runtime dependencies are unchanged: `canonicalize` 5.1.0, `jose` 6.2.12, `standardwebhooks` 1.1.1.

## SDK maintainer steps

1. Confirm `npm view @sess.si/sdk dist-tags --json` shows `next: 0.1.0-rc.10` and `latest: 0.0.0-stage`.
2. Tag this packet's merge commit (check it with `git show <sha>:release/sdk-next-candidate.json`):

   ```sh
   git tag v0.1.0 <sha>
   git push origin v0.1.0
   ```

3. **Publish approved SDK release** (`.github/workflows/release.yml`) runs `npm run check` at the tag, uploads the tested tarball and prints its SHA-256, which must equal the value above. For a stable version it derives the dist-tag `latest`.
4. Approve the `npm-release` environment. The job stages exactly the tested tarball, with provenance, on `latest`.
5. Check the stage, then approve it with npm 2FA:

   ```sh
   npm stage list @sess.si/sdk --json
   npm stage download <stage-id>
   shasum -a 256 sess.si-sdk-0.1.0-<stage-id>.tgz   # must equal the SHA-256 above
   npm stage view <stage-id>                         # tag must be latest
   npm stage approve <stage-id>                      # npm 2FA
   ```

6. The readback job checks integrity, the dist-tag and provenance. Then:

   ```sh
   npm view @sess.si/sdk@0.1.0 version license dist.integrity --json
   npm view @sess.si/sdk dist-tags --json            # latest: 0.1.0
   ```
