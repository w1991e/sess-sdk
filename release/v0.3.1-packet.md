# Release packet: @sess.si/sdk 0.3.1 on `latest`

This is a maintainer document and is not packed. Preparing it publishes nothing. The tag, the protected-environment approval and the npm 2FA stage approval are owner actions.

**Goal:** fix one defect, and nothing else.

- **The defect:** every released `verifyWebhook` (up to 0.3.0) refuses the webhook messages Sess sends for an Ask, with `WEBHOOK_INVALID_PAYLOAD`:
  - a respondent's `response.accepted` carries `ask_id`;
  - the Ask's own `ask.closed` is a second message type.
- **The fix:** 0.3.1 accepts both, checked exactly.
- **The release:** a patch version, so `latest` moves from `0.3.0` to `0.3.1` through the release workflow only, and `next` stays at `0.1.0-rc.10`.

**Authority:** the Sess founder, 2026-11-16 23:03Z item 1: "sdk 0.3.1: yes. A narrow release that fixes only the Ask webhook defect (ask_id accepted; ask.closed handled). ASTRA's verdict as an adapter contract change. Write the release steps for my keyboard and tell me when it is ready. It does not replace or delay 0.4.0."

## What SDK 0.3.1 contains

The `0.3.1` entry in [`CHANGELOG.md`](../CHANGELOG.md):

- **`response.accepted`** may carry `ask_id` (`ask_…`), checked as an Ask ID and returned as `WebhookEvent.ask_id`. Any other Session's message is unchanged.
- **`ask.closed`:**
  - exactly `type`, `event_id`, `ask_id`, `closed_by` (`max` or `owner`), `started` and `closed_at`, each checked;
  - its `event_id` must equal the `webhook-id` header;
  - returned as the new exported type `AskClosed`. `VerifiedWebhook` is the union of `WebhookEvent`, `AskClosed` and `WebhookChallenge`.
- **Unchanged:** unknown members are still refused. Signature, timestamp, header and body rules are unchanged, and authentication still happens before parsing.
- **The User-Agent:** `SDK_VERSION` is `0.3.1`.

**Not in it:**

- `decodeEvents` (it already accepts `ask_id` on Events);
- receipts, envelopes and bundles;
- the contract snapshot;
- runtime dependencies (`canonicalize` 5.1.0, `jose` 6.2.12, `standardwebhooks` 1.1.1, unchanged).

**Forward compatibility and the rest** stay in 0.4.0, which this release neither replaces nor delays.

**`@sess.si/mcp`, `@sess.si/openclaw` and `@sess.si/create-agent`** need no release for this: none imports `verifyWebhook`. The registry transition after publication moves the repository's consumers to 0.3.1.

## Maintainer steps (the owner's keyboard)

1. **Check the dist-tags:** `npm view @sess.si/sdk dist-tags --json` shows `latest: 0.3.0` and `next: 0.1.0-rc.10`.
2. **Find the squash commit on master** that merged this PR, and check it:
   ```sh
   git fetch origin
   git show <sha>:package.json | grep '"version"'          # "0.3.1"
   git show <sha>:release/sdk-next-candidate.json          # 0.3.1 and the SHA-256 above
   git merge-base --is-ancestor <sha> origin/master && echo on-master
   ```
3. **Dry runs** (local; nothing is uploaded), in a clean checkout of `<sha>`:
   ```sh
   git switch --detach <sha>
   npm ci --ignore-scripts && npm run build
   npm pack --dry-run                    # sess.si-sdk-0.3.1.tgz
   npm publish --dry-run --tag latest    # nothing is uploaded
   ```
4. **Tag and push:**
   ```sh
   git tag v0.3.1 <sha>
   git push origin v0.3.1
   ```
5. **Publish approved SDK release** (`.github/workflows/release.yml`) runs `npm run check` at the tag and prints the tested tarball's SHA-256, which must equal the value above. The dist-tag is `latest`.
6. **Approve the `npm-release` environment.** The job stages exactly the tested tarball, with provenance, on `latest`.
7. **Check the stage, then approve it with npm 2FA:**
   ```sh
   npm stage list @sess.si/sdk --json
   npm stage download <stage-id>
   shasum -a 256 sess.si-sdk-0.3.1-<stage-id>.tgz   # must equal the SHA-256 above
   npm stage view <stage-id>                         # tag: latest, version 0.3.1
   npm stage approve <stage-id>                      # npm 2FA
   ```
8. **Read it back:**
   ```sh
   npm view @sess.si/sdk@0.3.1 version license dist.integrity --json
   npm view @sess.si/sdk dist-tags --json            # latest: 0.3.1, next: 0.1.0-rc.10
   ```
   Smoke test, in an empty directory:
   ```sh
   npm install --save-exact @sess.si/sdk@0.3.1
   node -e "import('@sess.si/sdk/webhooks').then(m=>console.log(typeof m.verifyWebhook))"   # function
   ```
9. **Registry transition** in one reviewed PR on master after step 8: `npm run pin:update`; in `adapters/mcp`, `npm run sdk:switch-to-registry -- --apply`; OpenClaw's `sdk.evidence` names 0.3.1. The prepared record is removed.

**Rollback:** `npm dist-tag add @sess.si/sdk@0.3.0 latest`. Do not unpublish.
