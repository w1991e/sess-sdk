## What SDK 0.2.0 contains

The `0.2.0` entry in [`CHANGELOG.md`](../CHANGELOG.md):

- **A rating in `sess.ask`:** a field `{ type: 'rating' }`, with the typed `rating: { low?, high? }` shape for `sessions.create()` and `publish()`.
- **Respondents in `sess.ask`:** `respondents: { max }` makes one link for many people (a Sess Ask). The handle has `read()` and `close()`, and `sess.asks.retrieve()` and `sess.asks.close()` are Advanced.
- **Unchanged:** without `respondents`, `sess.ask` is unchanged.
- **The User-Agent:** `SDK_VERSION` is `0.2.0`, so the default `User-Agent` names the new version.

Runtime dependencies are unchanged: `canonicalize` 5.1.0, `jose` 6.2.12, `standardwebhooks` 1.1.1. The contract snapshot is unchanged from rc.8; the rating and `/v1/asks` types are written by hand.

**The Ask on Sess production:** the Ask's routes are off on Sess production until the founder's window turns them on (the Monday window, founder 17:15Z). Until then a production key's `respondents` call is refused as not found. The rating field works on production now.

## Maintainer steps

1. Confirm `npm view @sess.si/sdk dist-tags --json` shows `latest: 0.1.1` and `next: 0.1.0-rc.10`.
2. Tag this packet's merge commit on master (check it with `git show <sha>:release/sdk-next-candidate.json`):

   ```sh
   git tag v0.2.0 <sha>
   git push origin v0.2.0
   ```

3. **Publish approved SDK release** (`.github/workflows/release.yml`) runs `npm run check` at the tag, uploads the tested tarball and prints its SHA-256, which must equal the value above. For a stable version it derives the dist-tag `latest`.
4. Approve the `npm-release` environment. The job stages exactly the tested tarball, with provenance, on `latest`.
5. Check the stage, then approve it with npm 2FA:

   ```sh
   npm stage list @sess.si/sdk --json
   npm stage download <stage-id>
   shasum -a 256 sess.si-sdk-0.2.0-<stage-id>.tgz   # must equal the SHA-256 above
   npm stage view <stage-id>                         # tag must be latest
   npm stage approve <stage-id>                      # npm 2FA
   ```

6. The readback job checks integrity, the dist-tag and provenance. Then:

   ```sh
   npm view @sess.si/sdk@0.2.0 version license dist.integrity --json
   npm view @sess.si/sdk dist-tags --json            # latest: 0.2.0
   ```

7. **Registry transition,** in one reviewed PR on master after step 6. Consumers move from `0.1.1` to `0.2.0`, and the prepared record is removed.
   - `npm run pin:update`.
   - In `adapters/mcp`: `npm run sdk:switch-to-registry -- --apply`.
   - By hand: `adapters/openclaw/compatibility.json` `sdk.evidence` names 0.2.0 and its release run.
   - The references `pin:update` does not touch:
     - `docs/compatibility.md`, `docs/migration.md`, `docs/releasing.md`;
     - `.github/ISSUE_TEMPLATE/bug.yml`;
     - `examples/quickstart-node/README.md`, `examples/recipes/README.md`;
     - the status lines in `adapters/mcp/README.md` and `adapters/openclaw/README.md`.
