# Release packet: `@sess.si/create-agent@0.1.0`

Maintainer document; not packed. Preparing this release publishes nothing. The tag, the
`npm-create-agent-release` environment approval and the npm 2FA stage approval are a maintainer's
actions. This is step 5 of [the 0.1.0 packet](../../release/v0.1.0-packet.md): the
`create-agent-v0.1.0` tag comes last, after `mcp-v0.1.0` and `openclaw-v0.1.0`, and should follow the
SDK's `v0.1.0` closely, because the root README's `npm create @sess.si/agent@latest` serves the
`0.0.0-stage` placeholder until it runs.

## What 0.1.0 contains

The `0.1.0` entry in [`CHANGELOG.md`](../CHANGELOG.md). Compared with `0.1.0-rc.6`:

- A stable version: the release workflow derives dist-tag `latest`. `next` stays at `0.1.0-rc.6`.
- The template depends exactly on `@sess.si/sdk` `0.1.0` (published on `latest`, SHA-256
  `a0745188bd53feb3eda2fe99ed1624d79db86a136ae4d7c5492cb0786de99b97`, the pin in
  [`release/sdk-candidate.json`](../../release/sdk-candidate.json)); rc.6 pinned `0.1.0-rc.8`.
- User-Agent `sess-create-agent/0.1.0`.
- The README, the package description and the `--help`/usage line name
  `npm create @sess.si/agent@latest` (was `@next`).
- The starter repository (`w1991e/sess-agent-starter`) receives the same template bytes in its own
  PR, merged after this one (its CI checks parity against sess-sdk master).

## Setup state

The one-time setup is done. `0.1.0-rc.6` is on `next`; the deprecated `0.0.0-stage` placeholder is on
`latest`. There is no bootstrap stage to reject.

Before tagging, check that the GitHub environment `npm-create-agent-release` still has its required
reviewer and its `create-agent-v*` tag rule. Also check that the stage-only trusted publisher on
npmjs.com is still bound to:

- repository `w1991e/sess-sdk`;
- workflow `create-agent-release.yml`;
- environment `npm-create-agent-release`.

## Maintainer steps

1. Confirm the reviewed PR carrying this packet is merged and its CI is green on master, and that
   `mcp-v0.1.0` and `openclaw-v0.1.0` have run. Note the merged master commit `<sha>` and check that
   it is version `0.1.0`: `git show <sha>:create-agent/package.json | grep '"version"'`.
2. Tag that exact commit and push the tag:

   ```sh
   git tag create-agent-v0.1.0 <sha>
   git push origin create-agent-v0.1.0
   ```

3. The workflow **Publish approved create-agent release**
   (`.github/workflows/create-agent-release.yml`) starts. Its prepare job runs the guards and their
   self-test, `npm ci --ignore-scripts`, template parity, the build and the create-agent tests, the
   pack and the clean registry install of that exact tarball. It derives dist-tag `latest` and prints
   the SHA-256 and integrity in the run summary. Both must equal the values above.
4. Approve the `npm-create-agent-release` environment for the publish job. It stages exactly the
   tested tarball with provenance on dist-tag `latest`.
5. Check and approve the stage with npm 2FA:

   ```sh
   npm stage list @sess.si/create-agent --json
   npm stage download <stage-id>
   shasum -a 256 sess.si-create-agent-0.1.0-<stage-id>.tgz   # must equal the SHA-256 above
   npm stage view <stage-id>                      # tag must be latest
   npm stage approve <stage-id>                   # npm 2FA
   ```

6. The readback job checks registry integrity, dist-tag, dependencies and provenance.
7. Read back yourself, then run the initializer from the registry in an empty directory:

   ```sh
   npm view @sess.si/create-agent@0.1.0 version license dist.integrity dist.attestations --json
   npm view @sess.si/create-agent dist-tags --json   # latest: 0.1.0; next: 0.1.0-rc.6
   npm create @sess.si/agent@latest my-agent -- --no-run
   grep '"@sess.si/sdk"' my-agent/package.json      # must be "0.1.0"
   ```

   Then `node scripts/check-latest-release.mjs 0.1.0` (step 6 of the 0.1.0 packet).
