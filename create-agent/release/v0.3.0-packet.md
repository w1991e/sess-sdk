# Release packet: `@sess.si/create-agent@0.3.0`

Maintainer document; not packed. **Prepared, not published.** Preparing this release publishes
nothing. The tag, the `npm-create-agent-release` environment approval and the npm 2FA stage approval
are a maintainer's actions. This is the last car of step 8 of
[the SDK 0.5.0 packet](../../release/v0.5.0-packet.md): the `create-agent-v0.3.0` tag comes after
`mcp-v0.5.0` and `openclaw-v0.3.0`. The orchestrator pushes no release tag.

The registry has `0.2.0` on `latest` (since 2026-11-19T21:53:22Z, read 2026-11-22; its integrity
equals [release/v0.2.0-packet.md](v0.2.0-packet.md)) and `0.1.0-rc.6` on `next`. `0.3.0` is stable:
the release workflow derives dist-tag `latest`. `next` stays at `0.1.0-rc.6`. The agent
`@sess.si/create-agent` 0.3.0 writes must never depend on `@sess.si/sdk` 0.4.0: its template names
exactly `0.5.0`, and the root `check:pin` and the workflow's template parity refuse anything else.

## What 0.3.0 contains

The `0.3.0` entry in [`CHANGELOG.md`](../CHANGELOG.md). Compared with `0.2.0`:

- The template depends exactly on `@sess.si/sdk` `0.5.0` (published on `latest`, SHA-256
  `84f6e005a849158d149100358c75d576b0725178f734aa0d7f4ced22e79c7f24`, the pin in
  [`release/sdk-candidate.json`](../../release/sdk-candidate.json)); 0.2.0 pinned `0.4.0`.
- Sess's tighter text limits in the template: each plan option is "idea, part of day", such as
  `Picnic in the park, afternoon`, at most 30 characters; the ideas in `template/weather.mjs` are
  shorter, and the template README's numbers follow (#77).
- User-Agent `sess-create-agent/0.3.0`.
- Nothing else in the packed files (`index.mjs`, `template/`, `README.md`, `LICENSE`,
  `package.json`) changed since `create-agent-v0.2.0`:
  `git diff create-agent-v0.2.0 -- create-agent/index.mjs create-agent/template create-agent/README.md create-agent/LICENSE create-agent/package.json`
  shows only `package.json`'s version and `template/README.md`, `template/agent.mjs`,
  `template/package.json` and `template/weather.mjs`.
- The starter repository (`w1991e/sess-agent-starter`) receives the same template bytes in its own
  PR, merged after this one (its CI checks parity against sess-sdk master): step 9 of the SDK 0.5.0
  packet.

## Maintainer steps

1. Confirm the reviewed PR carrying this packet is merged and its CI is green on master, and that
   `mcp-v0.5.0` and `openclaw-v0.3.0` have run. Note the merged master commit `<sha>` and check that
   it is version `0.3.0` with a template on SDK `0.5.0`:
   `git show <sha>:create-agent/package.json | grep '"version"'` and
   `git show <sha>:create-agent/template/package.json | grep '"@sess.si/sdk"'`.
2. Tag that exact commit and push the tag:

   ```sh
   git tag create-agent-v0.3.0 <sha>
   git push origin create-agent-v0.3.0
   ```

3. The workflow **Publish approved create-agent release**
   (`.github/workflows/create-agent-release.yml`) starts. Its prepare job runs the guards and their
   self-test, `npm ci --ignore-scripts`, template parity, the build and the create-agent tests, the
   pack and the clean registry install of that exact tarball ("installed @sess.si/sdk@0.5.0 …
   integrity equals the pin"). It derives dist-tag `latest` and prints the SHA-256 and integrity in
   the run summary. Both must equal the values above.
4. Approve the `npm-create-agent-release` environment for the publish job. It stages exactly the
   tested tarball with provenance on dist-tag `latest`.
5. Check and approve the stage with npm 2FA:

   ```sh
   npm stage list @sess.si/create-agent --json
   npm stage download <stage-id>
   shasum -a 256 sess.si-create-agent-0.3.0-<stage-id>.tgz   # must equal the SHA-256 above
   npm stage view <stage-id>                      # tag must be latest
   npm stage approve <stage-id>                   # npm 2FA
   ```

6. The readback job checks registry integrity, dist-tag, dependencies and provenance. A good result
   prints "release-guard: verified @sess.si/create-agent@0.3.0 on latest, integrity and provenance".
7. Read back yourself, then run the initializer from the registry in an empty directory:

   ```sh
   npm view @sess.si/create-agent@0.3.0 version license dist.integrity dist.attestations --json
   npm view @sess.si/create-agent dist-tags --json   # latest: 0.3.0; next: 0.1.0-rc.6
   npm create @sess.si/agent@latest my-agent -- --no-run
   grep '"@sess.si/sdk"' my-agent/package.json      # must be "0.5.0"
   ```
