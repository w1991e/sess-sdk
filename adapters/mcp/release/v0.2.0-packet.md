# Release packet: `@sess.si/mcp@0.2.0`

Maintainer document; not packed. Preparing this release publishes nothing. The owner's actions are the tag `mcp-v0.2.0`, the `npm-mcp-release` environment approval and the npm 2FA stage approval. The orchestrator pushes no release tag (founder 2026-11-07 01:35Z).

The registry has `0.1.1` on `latest` and `0.1.0-rc.4` on `next`. `0.2.0` is stable: the release guard derives the dist-tag `latest`, and `next` stays at `0.1.0-rc.4`.

## What 0.2.0 contains

- The `0.2.0` entry in CHANGELOG.md (proposed, for the founder's signature): the rating field in `sess_ask` (and the raw `rating` field in `sess_request`/`sess_publish`); Advanced `respondents` on `sess_ask` (a Sess Ask), read by `sess_response`, whose state may be `closed`.
- Tool schemas `sess-mcp-tools/5` (was `/4`). The five tool names are unchanged. `sess_ask` still requires only `question` and `fields`.
- The runtime SDK dependency, exact: `@sess.si/sdk@0.2.0` from the registry (sha256 `38562280ee9cf6ecb81d0dd5d15c5846854b7e2debc4a51fb36b078b89e6c7ee`). Published 2026-11-07, release run 42330791897, tag `v0.2.0` on `cf293faa`.
- `mcpName` stays `si.sess/sess`. `server.json` names 0.2.0 for the server and the npm package.
- MCP cannot close an Ask: an Ask started from MCP ends at its cap or its deadline. The SDK has `sess.asks.close`; MCP has no matching tool, and none is added in this release.

## Maintainer steps

1. Confirm the reviewed PR carrying this packet is merged and its CI is green on master. Note the
   merged master commit `<sha>` and check that it is version `0.2.0`:
   `git show <sha>:adapters/mcp/package.json | grep '"version"'`.
2. Tag that exact commit and push the tag:

   ```sh
   git tag mcp-v0.2.0 <sha>
   git push origin mcp-v0.2.0
   ```

3. The workflow **Publish approved MCP adapter release** (`.github/workflows/mcp-release.yml`)
   starts. Its prepare job runs the release guards, `npm run check` and `npm audit` at the tag,
   uploads the tested tarball and prints its SHA-256 in the run summary. That SHA-256 must equal
   the value above, and the derived dist-tag must be `latest`.
4. Approve the `npm-mcp-release` environment for the publish job. It stages exactly the tested
   tarball with provenance on dist-tag `latest` (`npm stage publish`; nothing is installable yet).
5. Check and approve the stage with npm 2FA:

   ```sh
   npm stage list @sess.si/mcp --json
   npm stage download <stage-id>
   shasum -a 256 sess.si-mcp-0.2.0-<stage-id>.tgz   # must equal the SHA-256 above
   npm stage view <stage-id>                        # tag must be latest
   npm stage approve <stage-id>                     # npm 2FA
   ```

6. The readback job waits up to 60 minutes for the approval, then checks version, repository and
   directory, registry integrity, dist-tag, dependencies and provenance. If it timed out, re-run
   the failed jobs after approving.
7. Read back yourself:

   ```sh
   npm view @sess.si/mcp@0.2.0 version dependencies dist.integrity dist.attestations --json
   npm view @sess.si/mcp dist-tags --json     # latest: 0.2.0; next stays 0.1.0-rc.4
   ```

   `dist.integrity` must equal the integrity above, `dependencies` must name
   `"@sess.si/sdk": "0.2.0"`, and `dist.attestations.provenance` must be present.
