# Release packet: `@sess.si/mcp@0.4.0`

Maintainer document; not packed. **Prepared, not published.** Preparing this release publishes nothing. The owner's actions are the tag `mcp-v0.4.0`, the `npm-mcp-release` environment approval and the npm 2FA stage approval. This is step 3 of [the SDK 0.4.0 packet](../../release/v0.4.0-packet.md): it goes to the owner's keyboard after the registry transition merges, before `openclaw-v0.2.0` and `create-agent-v0.2.0`. The orchestrator pushes no release tag.

The registry has `0.3.0` on `latest` (since 2026-11-10T22:12:00Z, read 2026-11-18) and `0.1.0-rc.4` on `next`. `0.4.0` is stable: the release guard derives the dist-tag `latest`, and `next` stays at `0.1.0-rc.4`. Until 0.4.0 is published, `latest` stays 0.3.0. `@sess.si/mcp` 0.4.0 must never ship on `@sess.si/sdk` 0.3.0: `package.json` and the lock name exactly 0.4.0 from the registry, and the root `check:pin` and the release workflow's `setup --require-registry` refuse anything else.

## Maintainer steps

1. Confirm the reviewed PR carrying this packet is merged and its CI is green on master. Note the
   merged master commit `<sha>` and check that it is version `0.4.0`:
   `git show <sha>:adapters/mcp/package.json | grep '"version"'`.
2. Tag that exact commit and push the tag:

   ```sh
   git tag mcp-v0.4.0 <sha>
   git push origin mcp-v0.4.0
   ```

3. The workflow **Publish approved MCP adapter release** (`.github/workflows/mcp-release.yml`)
   starts. Its prepare job runs the release guards, `npm run check` and `npm audit` at the tag,
   uploads the tested tarball and prints its SHA-256 in the run summary. That SHA-256 must equal
   the value above, and the derived dist-tag must be `latest`.
4. Approve the `npm-mcp-release` environment for the publish job. It stages exactly the tested
   tarball with provenance on dist-tag `latest` (`npm stage publish`; nothing is installable yet).
5. Check and approve the stage with npm 2FA:

   ```sh
   npm stage list @sess.si/mcp --json
   npm stage download <stage-id>
   shasum -a 256 sess.si-mcp-0.4.0-<stage-id>.tgz   # must equal the SHA-256 above
   npm stage view <stage-id>                        # tag must be latest
   npm stage approve <stage-id>                     # npm 2FA
   ```

6. The readback job waits up to 60 minutes for the approval, then checks version, repository and
   directory, registry integrity, dist-tag, dependencies and provenance. If it timed out, re-run
   the failed jobs after approving.
7. Read back yourself:

   ```sh
   npm view @sess.si/mcp@0.4.0 version dependencies dist.integrity dist.attestations --json
   npm view @sess.si/mcp dist-tags --json     # latest: 0.4.0; next stays 0.1.0-rc.4
   ```

   `dist.integrity` must equal the integrity above, `dependencies` must name
   `"@sess.si/sdk": "0.4.0"`, and `dist.attestations.provenance` must be present.
