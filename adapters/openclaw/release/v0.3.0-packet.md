# Release packet: `@sess.si/openclaw@0.3.0`

Maintainer document; not packed. **Prepared, not published.** Preparing this release publishes
nothing. The tag, the `npm-openclaw-release` environment approval and the npm 2FA stage approval
are a maintainer's actions. This is the second car of step 8 of
[the SDK 0.5.0 packet](../../../release/v0.5.0-packet.md): after `mcp-v0.5.0`, before
`create-agent-v0.3.0`. The orchestrator pushes no release tag.

The registry has `0.2.0` on `latest` (since 2026-11-19T21:47:12Z, read 2026-11-22; its integrity
equals [release/v0.2.0-packet.md](v0.2.0-packet.md)) and `0.1.0-rc.5` on `next`. `0.3.0` is stable:
the release guard derives dist-tag `latest`. `next` stays at `0.1.0-rc.5`; the release does not move
it. `@sess.si/openclaw` 0.3.0 must never ship on `@sess.si/sdk` 0.4.0: `package.json` and the lock
name exactly 0.5.0, and `scripts/registry-sdk.mjs`, the root `check:pin` and the release guard
refuse anything else.

## Maintainer steps

1. Confirm the reviewed PR carrying this packet is merged and its CI is green on master, and that
   `mcp-v0.5.0` has run. Note the merged master commit `<sha>` and check that it is version
   `0.3.0` on SDK `0.5.0`:
   `git show <sha>:adapters/openclaw/package.json | grep -E '"version"|"@sess.si/sdk"'`.
2. Tag that exact commit and push the tag:

   ```sh
   git tag openclaw-v0.3.0 <sha>
   git push origin openclaw-v0.3.0
   ```

3. The workflow **Publish approved OpenClaw adapter release**
   (`.github/workflows/openclaw-release.yml`) starts. Its prepare job runs the guards and their
   self-test, `npm ci`, build, typecheck, tests, the packed check against the registry SDK and a
   real OpenClaw host ("PASS host-install"), and `npm audit`. It uploads the tested tarball and
   prints its SHA-256 in the run summary. That SHA-256 must equal the value above, and the derived
   dist-tag must be `latest`.
4. Approve the `npm-openclaw-release` environment for the publish job. It stages exactly the tested
   tarball with provenance on dist-tag `latest` (`npm stage publish`; nothing is installable yet).
5. Check and approve the stage with npm 2FA:

   ```sh
   npm stage list @sess.si/openclaw --json
   npm stage download <stage-id>
   shasum -a 256 sess.si-openclaw-0.3.0-<stage-id>.tgz   # must equal the SHA-256 above
   npm stage view <stage-id>                             # tag must be latest
   npm stage approve <stage-id>                          # npm 2FA
   ```

6. The readback job waits for the approval, then checks version, integrity, the `latest` dist-tag,
   repository and directory, dependencies and peer dependencies, and provenance. If it timed out,
   re-run the failed jobs after approving. A good result prints "Verified @sess.si/openclaw@0.3.0,
   latest, tested integrity and provenance metadata."
7. Read back yourself:

   ```sh
   npm view @sess.si/openclaw@0.3.0 version dependencies peerDependencies dist.integrity dist.attestations --json
   npm view @sess.si/openclaw dist-tags --json     # latest: 0.3.0; next stays 0.1.0-rc.5
   ```

   `dist.integrity` must equal the integrity above, `dependencies` must name
   `"@sess.si/sdk": "0.5.0"` (never 0.4.0), `peerDependencies` must equal
   `{"openclaw":"2026.10.3 || 2026.10.7"}`, and `dist.attestations.provenance` must be present.
